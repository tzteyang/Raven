applicability or its delivery before proposing any change. Loading is not proof of application; a disappointing
outcome does not by itself identify the cause. Distinguish content, scope, selection, loading, application,
execution, evaluation and evidence faults. Refer only to the supplied method targets and evidence references.

Return at most one issue per method. State the reason, actual evidence and smallest fields needing correction.
Use content.guidance, content.support_kind or the specific content.condition fields. A scope issue may change
only content.condition fields. Selection, loading, application, execution and evaluation faults grant no edits
to a correct method. Use an empty fields list when more investigation or a host mechanism change is needed.

independent verification, not permission to publish or ignore an observed failure. Return no issues when the
observations justify none. Submit only submit_experience_diagnoses.
