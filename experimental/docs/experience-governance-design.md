本方案为 Harness 生成与改造管线定义共用的经验准入、使用和修订协议。Rubric Builder、Curator 及其他角色保留各自的经验内容、评审方法和验证方式，通过公共协议积累可追溯、可验证、可撤销的经验。

状态：公共协议已接入 Rubric Builder 与 Curator。来源、准入、实际使用、有限修订和失效恢复已实现；功能验证与实际收益分别报告，不能从闭环接通推导出跨任务收益。

## 目标与设计边界

经验是从可追溯的实践记录中提炼、具有适用范围、能够指导后续行为，并允许被验证、修订和撤销的可复用知识。原始观察可以直接保存；只有满足准入规则的派生经验才能进入正式指导。

共同要求是：各角色共享经验的准入、版本、使用记录和修订协议；各角色保留自己的内容形式、提炼方式、评审方法和效果验证。Rubric Builder 的构建经验与 Curator 的改造经验分别管理，通过同一协议接入。

范围覆盖 Harness 生成与改造管线中的经验积累，包括归因、构建、评价和评审角色。经验可表达为原则、方法、案例或带资源的方法包。事实材料、外部要求和任务产物继续使用各自的业务模型；公共协议保留其来源与权威边界，不把它们都改造成同一种经验。

本设计约束共享行为，不预先规定全部字段或数据库结构。首个实现采用本地持久化与角色接入组件；现有记录能够引用的内容继续引用。扩展到新角色不应要求公共层认识其业务状态或评分含义。

## 公共协议与角色接入

公共层负责保存和校验版本、编排评审与验证、根据准入规则采用经验，以及记录使用和变更。角色接入组件负责解释经验内容、匹配适用情境、提炼候选、评审与验证、提供归因结果和生成消费形式。

| 信息 | 必须能够回答的问题 |
| --- | --- |
| 经验及其版本 | 内容是什么，面向哪个角色和阶段，适用于什么条件，当前是否生效 |
| 依据记录 | 原始事实是什么，解释或推断是什么，来源和产物是否仍可核验 |
| 评审与准入记录 | 按什么规则验证了哪个候选及基线，结论和允许采用的范围是什么 |
| 使用记录 | 哪次执行实际加载了哪些版本和内容，产生了哪些可观察结果 |

这四类是信息职责，不要求实现四张表或四个独立服务。候选变更引用这些记录，说明新增、修订、合并、范围调整或停用的目标；生效经验是已通过准入的版本。

| 接入能力 | Rubric 构建侧 | Curator 侧 |
| --- | --- | --- |
| 经验内容 | 标准构建、层级组织、证据选择和评价修订经验 | 机制归因、改造范围、实现与回归经验 |
| 提炼依据 | rubric 版本、评价记录、元评审和独立检查 | Harness 版本、改造记录、执行轨迹和反馈 |
| 内容评审 | 要求是否有依据、是否可判定、是否过度概括 | 因果解释是否有依据、方法是否适用于当前机制 |
| 效果验证 | 独立正反例、反例分析和评价回归 | 可比较条件下的真实执行、目标行为和既有能力回归 |
| 使用方式 | 构建指导与必要的检查资源 | 归因或改造指导、案例及适用的方法包 |

提炼者可以是现有 Meta Reviewer 或其他角色；内容评审可以使用模型、程序或两者组合。它们提出候选和评审意见，宿主根据独立证据及预先确定的规则决定采用。职责独立不强制使用不同模型，也不意味着模型之间的一致意见构成独立验证。

## 经验内容与上下文表达

principle 和 procedure 是指导性文本的两种形式，不作为公共层对所有经验内容的固定枚举。角色也可以提供案例或程序资源，但必须声明自己的内容结构与使用方式，并接受对应的准入检查。Curator 的 process / behavior 表达证据能支持的结论范围，与指导表达形式分别管理；不把一侧的内容枚举或支持门槛扩展为所有角色的统一规定。

判断原则 principle 是对一类决策中应保持的关系、应避免的失真或取舍依据的概括。它保留经验背后的判断依据，使使用者面对不同于历史案例的新情境时仍能选择和检查做法。原则通常不规定唯一操作步骤，也不因命名为原则就获得更高权威。

操作方法 procedure 是针对一类问题组织起来的处理过程，包含触发条件、必要动作、结果分支以及检查与停止条件。它将判断依据转成可重复执行和复查的行动，减少遗漏和无效探索。执行完步骤不等于已经达成目标。

原则帮助判断做法是否合理，方法帮助落实和检查做法。两者不强制成对，一项方法可以满足多条原则；经验引用关系本身不授予额外权限。

进入 agent 上下文时，先提供固定的定义与使用说明，再提供本轮适用的条目。对于采用这两种文本形式的角色，固定说明如下；示例为中文说明，代码中的基础提示词按仓库语言规范实现。

```text
以下内容是适用于本轮工作的已采用经验，用于选择和改进工作方式。
它们不能覆盖当前任务的明确要求、外部约束或授权范围。

判断原则 principle：对一类问题中应保持的关系、取舍依据和应避免错误的概括。
价值：帮助你在不同情境中判断一个做法为什么合理，避免照搬旧案例。
用法：先核对适用条件，再据此比较做法、解释选择和检查结果。

操作方法 procedure：针对一类问题组织起来的处理过程，包括开始条件、
操作步骤、结果分支以及检查与停止条件。
价值：把判断依据落实为可执行、可复查的行动，减少遗漏与无效探索。
用法：确认输入和触发条件，依观察结果执行分支，并检查实际结果。

原则约束做法的合理性，方法组织具体行动；完成步骤不代表已经通过验收。
类型标签不代表权威等级，也不意味着在所有任务中成立。
```

原则正文采用“适用情境、判断依据、理由”，必要时补一个反例；方法正文采用“适用时机、步骤、检查与停止”。这些是文本写作约定，不据此增加一套必填数据库字段。公共层补入真实版本引用和作用范围，不能让模型通过文本自报生效状态。

Rubric 示例：原则要求父子关系有必要条件依据；方法通过核对来源、明确共同适用条件、寻找父项成立而子项不成立的反例来检查归属。Curator 示例：原则要求区分能力不存在与能力未被使用；方法沿注册、暴露、触发、执行和结果消费的实际记录定位断点。

JSON 保存结构化记录；上下文采用简洁的 Markdown 指导或角色需要的资源形式。渲染应确定性地保留已验证内容，不临时调用模型重写。关键条件不能被截断，完整依据按可见权限引用。稳定且完整的方法可以生成 Skill，其内容及依赖必须绑定同一个已采用版本，不能另行维护一份无准入记录的指导。

## 候选准入与采用流程

固定顺序为：留存事实 → 提出候选变更 → 检查评审条件 → 固定验证方案 → 执行验证 → 限定范围采用 → 记录实际使用。任何经验的新增或修订都经过这条流程。

| 环节 | 通过条件与控制分支 |
| --- | --- |
| 留存事实 | 保存实际观察、来源与版本；缺失信息标为缺失，推断与观察分开 |
| 提出候选 | 说明改变什么、为何需要改变、希望改善什么；没有可提炼结论时只保存观察 |
| 检查评审条件 | 来源可核验，内容及范围明确，新增价值可检查，没有未解决的权威冲突；失败时记录不采用或待证原因 |
| 固定验证方案 | 绑定候选、基线、相关经验组合、案例及验证规则；预先说明成功、失败和不确定条件 |
| 执行验证 | 验证预期收益、适用边界及不可接受的退化；证据不足或执行错误均不得按通过处理 |
| 限定范围采用 | 宿主确认验证仍对应当前版本和条件，再原子更新生效版本及采用记录 |
| 记录使用 | 选择适用条目并保存实际加载内容；结果和反例进入后续归因 |

内容评审检查“这条经验的说法是否成立且值得尝试”，效果验证检查“采用它是否产生了声称的作用”。模型评审可以帮助构造验证假设，但不能自行生成期望答案，再用这些答案证明自己的经验有效。独立证据可来自环境状态、程序验证、已确认反馈或受控回放，不要求每次都请人审阅。

验证目标随变更而定。新增经验可以要求补足原有缺口；纠错要求降低目标错误并保护正确行为；合并或简化可以要求效果不退化且减少重复。公共层不内置一个通用分数，也不机械要求每种变更都提升最终得分。验证指标、不可退化项及重复次数由角色策略预先确定；策略缺失时不自动采用。

对原则，应重点寻找反例并核对适用边界；对方法，应检查关键动作是否发生、结果分支及停止条件是否有效。观察到结果改善只能支持经验的效果主张，不能直接证明其解释就是唯一原因。

候选可以在隔离回放中试用，不能因此进入正式指导。跨任务采用需要未参与提炼的任务证据；更换案例编号或重复同一输入不会产生新的独立证据。模型随机性可能影响结论时按事先确定的方案复核，不能持续重试直到偶然通过。

生命周期只需区分候选、生效和停用。不采用、证据不足、被替换及停用原因保存在决策记录中。内容已经过审查、获得某种证据支持与允许正式使用分别判断；角色已有的 supported 等结论不自动映射为公共生效状态。无新内容、证据或条件变化时不自动重跑同一候选；新增验证材料后可重新评估。

## 归因驱动的增量修订

统一归因协议要求回答六个问题：观察到什么问题；问题位于哪个角色或阶段；哪些经验版本与机制实际参与；什么证据支持当前解释以及还有什么不确定；拟修改哪个对象和哪些部分；怎样验证修正有效。各角色保留自己的原因分类，公共层不将所有领域状态塞进一个通用枚举。

归因沿实际作用链排查：经验是否被选中 → 内容是否进入上下文或资源是否被加载 → 是否出现与方法有关的行为 → 执行机制是否完成预期动作 → 结果是否被正确评价。加载日志和模型自述不能单独证明经验被正确运用。

| 证据支持的问题 | 允许考虑的修改对象 |
| --- | --- |
| 经验内容错误 | 对应条目的局部内容 |
| 当前条件不符合经验前提 | 适用范围或选择规则 |
| 合适经验没有加载或被截断 | 选择、加载和上下文组装 |
| 经验已加载但未落实 | 表达、行动方法或承载机制，依据具体证据定位 |
| 工具、环境或实现故障 | 对应执行机制 |
| 评审或验证失效 | 评审依据、验证器及受影响的采用结论 |

归因产生候选变更，不直接覆盖生效经验。宿主将允许修改的对象和范围绑定到当前基线；未被归因涉及的内容保持不变。修订、合并、范围扩大或资源更新都形成新版本，重新经过准入；修改权限不能因为模型给出更宽泛的解释而扩大。

验证范围可以超过写入范围，以检查其他经验和角色的回归。测试时应包含实际共同加载的相关经验，避免逐条有效、组合后冲突。没有定位出原因时保存不确定性，不据此重写整套经验。

例一：Rubric Builder 的层级方法已被加载，但生成结果违反其必要条件原则。归因需要检查方法表述、步骤执行和生成过程，不能仅凭最终评价失败就认定原则错误。例二：Curator 的正确经验没有进入上下文。应先修复选择或加载，经验正文保持不变，再用相同条件检查加载和后续行为。

后续出现可信反证时，宿主可按既定规则先停止该经验的后续使用，并保存原因，再调查和形成修订候选。回滚只能恢复仍满足当前条件的已验证旧版本；如旧版本也不适用，则保持停用，不强行恢复。

## 版本使用与权限边界

版本身份必须覆盖会改变含义或行为的内容，包括正文、适用范围、资源依赖及相关渲染方式。采用记录还需绑定基线组合、评审策略、验证输入和执行配置。验证后这些条件改变时，由依赖关系决定哪些结论需要重验；不能用旧回执无条件批准新内容，也不必重验无关对象。

采用和替换应当原子完成，并防止并发运行覆盖彼此的版本。中断恢复使用已保存的候选、基线和验证状态；重启不能将候选默认为生效。被替换或停用的历史仍然能够回溯。

使用记录保留消费角色及阶段、任务条件、选中的经验版本、实际渲染内容或资源引用，并关联执行记录。入选、加载、观察到应用行为是不同事实；无法证明应用时明确保留未知。

共享治理协议不意味着共享全部经验和原始材料。接收者可见范围由宿主控制；评价侧的保留答案、隐藏检查和未公开材料不能随经验正文进入 Curator 或 Worker。不同角色复用经验时，需要显式确认其受众、适用范围和验证依据。

外部明确要求与模型归纳经验采用不同的准入依据。外部要求首先核验来源、适用范围和冲突，作为相应角色应遵守的要求保留；不能因缺少效果提升而将其忽略。模型经验需要验证其主张和用途，反复使用或多模型赞同都不会把它提升为外部权威。显式外部要求相互冲突时保留冲突，不允许模型暗中选择较宽松的一方。

经验准入与产物准入相互独立。Curator 经验生效不等于其生成的 Harness 可以部署；Rubric 构建经验生效也不等于 rubric 或任务产物已通过验收。生成 Skill 或程序资源不授予执行和安装权限。

准入策略可以演进，但策略身份和版本由宿主管理；被评审的经验无权修改自己的准入规则。评审角色也可以积累经验，其经验同样通过协议验证，不能靠自我认可扩大采用权。

## 现有实现与接入路径

公共实现位于 experimental/harness/experience/governance.py；Governance 管理候选、生效和停用，Diagnosis 绑定允许修改的字段与当前基线，Decision 绑定独立证据和策略。GuidanceStore 将它嵌入既有 JSON；CuratorExperience 通过 GovernanceFile 接入已有 SQLite 证据库。SQLite 的 supported 是领域资格，公共记录才是实际采用的权威；两个记录承担不同职责。

| 接入部分 | 公共职责与领域职责 |
| --- | --- |
| Rubric 构建经验 | 来源、版本、采用及使用记录接入公共层；准则构建、独立回放和准确性规则保留在评价侧 |
| Curator 经验 | 复用事务、证据分组、撤销和检索；机制条件、过程与行为支持判断保留在 Curator 侧 |
| 经验归因修订 | 共用问题依据、影响对象、有限变更、替换与复验协议；保留各角色的诊断方法 |
| 运行接入 | 各角色固定自己的消费边界和实际指导包，公共层记录版本及准入依据，不强制相同任务粒度 |

采用一个小的公共模块和各角色的接入组件。公共模块管理来源与版本、决策及使用记录、替换和失效；领域组件负责内容校验、适用性、评审、验证和呈现。具体内容不能成为无人检查的任意字段包。SQLite 或 JSON 是存储实现选择，不能形成两套独立决定生效的权威记录。

共同实施顺序是：先固定两侧兼容基线与协议一致性场景，再复用已有状态及证据能力，分别完成 Rubric 的 R2 和 Curator 的 C2 接入；随后完成各自的上下文表达、归因修订及实际消费；最后分别验收。两侧使用同一公共协议，不要求采用相同的评分函数、来源数量或验证样本数。

旧记录保留原有受众、来源及采用依据。Rubric 经验不能因迁移自动成为 Curator 经验；Curator 的过程支持不能被转成业务收益。缺少新协议必需依据时保留历史、限制使用或补证，不静默追认未经验证的生效状态。所有状态映射和替换关系必须可审计。

结构化记录是权威来源，上下文和 Skill 是相应版本的派生表达。首版复用现有角色、有界调用、本地记录与事务，不新增独立检索服务、知识图谱或多层评审组织。具体字段、类名和存储布局在实现时收敛，三份文档的准入、权限和验收语义保持一致。

## 验收准则与实现约束

以下场景是实现的持续验收要求。对应边界已纳入共享治理、Rubric 和 Curator 测试；功能通过不代表所有任务上的经验收益已经成立。

| 场景 | 必须观察到的结果 |
| --- | --- |
| 同一协议接入 Builder 与 Curator | 生命周期和采用记录共用；经验内容及验证规则各自独立 |
| 候选缺少独立证据 | 可以留存，不能进入正式指导 |
| 明确存在反证或验证错误 | 不得按通过处理，并保留原因 |
| 经验扩大受众或任务范围 | 触发对应验证，不能继承原范围之外的采用资格 |
| 验证后内容或相关基线变化 | 旧回执不能批准新版本，重新检查受影响条件 |
| 正确经验未被加载 | 归因指向选择或加载，不直接改写经验正文 |
| 修订一条经验 | 无关条目保持不变，同时验证相关组合和受保护行为 |
| 多角色共享记录 | 可回溯但不泄露接收者不可见的材料和验证答案 |
| 上下文或 Skill 使用经验 | 含义、依赖和来源绑定已采用版本；明确说明类型定义与使用方式 |
| 替换中断或并发更新 | 不产生部分采用，不覆盖其他有效更新，历史可恢复 |

实现必须保留候选与生效的区分、来源与权威的区分，以及经验准入与产物验收的区分。默认不自动采用缺少明确策略或验证依据的候选。数值阈值、案例规模和重复次数由各角色的验证策略给出；缺省值不能绕过准入。

新增字段应能对应版本绑定、准入决策、适用性、使用归因或恢复中的明确用途。具体类名、存储布局和方法签名在实现时按现有代码约定收敛；它们不能改变上述协议、角色边界和验收语义。

## 首版实现边界

公共层只记录和检查协议，领域适配器负责执行评审、验证与渲染，没有新增服务或通用分数。指导通过确定性 Markdown 进入上下文；Skill 导出和经验资源安装不在首版中自动执行。

采用收据绑定内容、来源、基线、策略、渲染与验证输入。来源撤销或条件变化会使旧包恢复失败；候选不能通过重启、替换或回滚绕过准入。选择、加载、应用、执行和评价问题不会直接取得改写经验正文的权限。

留出验证通过比较运行的上下文标记阻止学习回写。它约束同一宿主运行中的学习路径，不替代操作系统隔离；需要跨进程验证时，验证执行器仍须提供独立目录和冻结输入。

当前共享协议支持显式多目标替换；两侧自动修订入口采用单项有界修订。自动发现同义项、批量合并、语义检索和 Skill 导出不属于首版能力。后续扩展仍须遵守本文的准入、权限与验证约束。
