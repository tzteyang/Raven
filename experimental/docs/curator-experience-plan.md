# Curator 经验闭环实施方案

本方案在已有 Curator 经验核心的基础上，完成公共准入协议接入、经验归因修订、Curator 实际消费和跨任务验证。已有核心能力保留，领域约束继续由 Curator 接入层负责。

上层指引：[Harness 管线经验准入与修订设计](experience-governance-design.md)。并列方案：[Rubric 构建经验闭环实施方案](rubric-experience-plan.md)。本方案同时记录实施约束和当前实现：C1 至 C5 已接通，C6 用独立对照报告实际效果；实现完成不等于广泛迁移收益成立。

## 目标与交接基线

学习对象是 Curator 调查、归因、改造和验证 Harness 的方法。经验主要表达为带适用条件的机制级改造策略：保留条件、行动、验证和边界，移除来源案例的实体、路径、数值及操作叙事。

交接资料为[Curator 经验机制开发交接](/root/.codex/worktrees/f5a8/Raven-SI/experimental/docs/curator-experience-handoff.md)及其关联设计。已有 experimental/experience/ 核心包含记录转换、Experience Builder、Experience Critic、有界修订、SQLite 存储、证据准入和只读检索。当前已通过 CuratorExperience 接入实际归因、生成、检查点和后续学习。

已接收完整经验核心及未提交的准入、检索和测试文件，并保留来源清单与内容摘要；当前生成、独立归因和历史接口采用适配方式接入。交接工作区未修改。

接收后已完成经验核心、公共治理、实际消费、恢复和后续学习回归，并运行真实模型构建与审查、真实审计、跨进程和获准归档验证。无归档配置时按跳过记录，提供有效归档后的验证已通过。这些结果证明相应功能边界，不直接证明新任务收益。

## 复用调整与新增能力

| 处理方式 | 能力及对齐方式 |
| --- | --- |
| 复用 | 来源授权和字段投影、证据版本、独立来源分组、矛盾保留、撤销失效 |
| 复用 | Builder 与 Critic 分工、有界修订、累计预算、租约与持久恢复 |
| 复用 | SQLite 事务、精确内容审查、只读检索、完整条目预算和指导包校验 |
| 调整 | Curator 专用阶段、机制状态和能力条件留在领域模型，公共层只管理协议 |
| 调整 | supported 等领域结论与公共生效状态分别表达，不把两个独立来源写成所有角色的统一规则 |
| 调整 | 适配当前独立归因阶段、类型化历史及实际生成接口 |
| 新增 | 从经验使用问题到局部变更、替换关系和独立复验的完整修订流程 |
| 新增 | 指导在 Curator 的真实消费、使用记录、检查点绑定和失效恢复 |
| 新增 | 无经验、历史参考及提炼指导的跨任务对照与成本观测 |

公共模块可复用现有事务存储和证据管理实现，但其接口不依赖 Curator 的机制状态或生成阶段。内容转换、经验提炼、语义评审及验证规则留在领域接入组件。源码目录和类型在实施时按依赖边界收敛，不复制出两套互不相认的生效状态。

保留 Experience Builder 与 Experience Critic 的职责名称，明确它们分别负责经验提炼和经验审查，区别于构建评价标准的 Rubric Builder 和评审评价装置的 Meta Reviewer。无需为每个公共步骤新增模型角色。

## 闭环角色与运行时序

一次 Curator 改造任务是经验消费边界。任务开始前读取已有经验；任务结束或获得新的有效观察后再学习，供后续独立任务使用。本轮提炼内容不回注本轮，当前改造仍由 Curator 自己完成。

| 顺序 | 行为与分支 |
| --- | --- |
| 1 准备指导 | 根据已知任务、阶段、作用域和宿主事实筛选可用经验，校验资格并固定本轮包；无适用经验时继续原流程 |
| 2 归因与生成 | 对应阶段读取固定包中适用内容，完成调查、选择、设计、实现和验证；经验不能代替当前代码与证据核查 |
| 3 保存实际使用 | 关联经验版本、实际文本、当前任务与 Harness 版本、归因和执行记录 |
| 4 转换新证据 | 生成过程结束后保存过程事实；后续 Worker 运行提供明确行为观察时，再关联行为证据 |
| 5 提炼与审查 | Experience Builder 提出候选，Experience Critic 审查表达、依据、范围及泄露；没有有用经验时允许为空 |
| 6 准入与修订 | 宿主按声明的收益及证据范围验证，满足公共协议后采用或替换，后续任务才能消费 |

过程完成与行为改善是两个不同时间点。生成或结构检查通过只能生成对应过程证据；不能在尚未运行 Worker 时填入行为收益。证据尚未形成时保留候选，后续新观察可触发补证。

原实现的 related 参考继续仅服务经验提炼，可包含范围内已审但未正式采用的方法。它不进入 Curator 的正式指导，不计作本轮新增证据，也不因被引用而获得更多支持。

## 内容表达与证据准入

Curator 当前的条件化策略主要属于操作方法。沿用 condition、guidance 和适用边界，按需要呈现原则与方法，不强制为了统一而把每条策略拆成两个对象。接收 agent 的上下文必须带有总纲规定的类型含义、价值及使用说明。

principle / procedure 描述指导内容如何发挥作用；process / behavior 描述证据能支持什么结论。两者正交，不进行相互映射。一个操作方法可以只有过程证据，也可以获得行为效果证据；其措辞必须与实际证据强度一致。

上下文默认采用简洁的 Markdown，至少表达适用情境、行动方法、验证方式、停止条件与证据支持范围。宿主补入版本引用和固定边界。保留结构化指导包用于校验与恢复；实际渲染内容也纳入快照及预算，不能只检查 JSON 大小。

内容评审继续检查案例泄露、过度具体或空泛、来源不支持、范围冲突，以及用 process 标签包装未验证行为效果的情况。Critic accept 只表示可保留为已审候选。

现有证据准入的关键边界全部保留：至少两个独立来源组、当前有效的精确审查、可核验的来源版本和没有未解释矛盾。相同运行、谱系或源摘要合并为一个证据组；根子作用域、复制、重放和同一联合改造的多输入不增加独立性。

| 结论范围 | 必须具备的证据 |
| --- | --- |
| process | 对应确切方法与来源版本的实际过程检查收据，且声明只涉及已检查的结构或过程属性 |
| behavior | 改造实际生效、明确观察、可比条件及相应结果；若声称增量改善，必须提供对照依据 |
| 跨任务改造收益 | 在未参与提炼的新任务上使用冻结经验，验证质量及不可退化项，并记录成本 |

接入公共协议后，supported 保留为领域证据结论，不自动等同于最终生效。宿主还需确认改善主张、适用范围、实际消费形式和对应验证方案满足准入。候选可在隔离试验中使用；冷启动时缺少证据不会授权其进入正常指导。

过程方法可凭其限定的过程目标和独立检查得到相应范围的采用资格，无需伪称已经提高业务结果。behavior 的效果主张按可比较结果验证；过程和行为准入都不能绕过公共的版本绑定及不可退化条件。跨任务收益验证用于检验所声称的迁移收益，不将单任务自我修订算作跨任务证据。

旧记录只证明联合处置时，不把整体收益分配给单项改动。当前历史中的 held=True 也不能直接转成明确行为支持：适配器必须核对真实观察、反馈依据和可比条件，将默认推断或缺失反馈保持为间接或未知。

旧候选不自动升级。旧 supported 迁移时保留原采用依据与结论范围，在补齐公共协议要求前不扩大受众或恢复为无条件生效。

## 归因驱动的经验修订

原实现用条件、指导原文和支持类型确定方法身份；相同表述积累新证据，改变正文则形成另一个身份。保留这个防止错误合并的能力，同时增加显式替换关系，连接被修订的方法和新候选，不能让两者无意中同时生效。

修订依据来自实际使用记录。诊断应指出问题所在角色或阶段、涉及经验版本、观察及不确定性，并区分内容错误、范围不合、未加载、未正确使用、执行机制故障与评价失效。Curator 既有机制归因继续解释机制层的问题；经验诊断只增加必要的版本关联。

宿主绑定当前基线和允许修改范围。Experience Builder 对获得授权的经验内容进行局部调整；未被涉及的已接受条目保持不变。新表述重新接受 Critic 内容审查、领域证据判断及对应效果验证，不能借用旧方法的支持数直接批准改变后的含义。

合并经验需要引用全部被影响对象并解释等效范围；不按词项相似自动合并，不因为累计次数多而获得权威。新版本采用时原子替换旧版本，同时保留来源、替换关系和决策历史。

可信反证或来源撤销可以先使相关经验退出后续使用。旧实现的 contested 与 retired 及其原因在迁移中保留；对外采用冲突待查、停用或失效的表达。不能通过更换 Critic 或新建同义条目抹去已知矛盾。

回滚不得自动推荐旧方法：先核对其来源、策略、适用条件和当前相关组合；仍然失效则保持停用。接收方包被撤销时必须拒绝按旧包恢复，而不是静默替换指导继续任务。

## Curator 接入与运行恢复

| 接入位置 | 需要落实的行为 |
| --- | --- |
| curator/workflow.py | 增加可选经验输入和调用边界，启动前固定包，结束后记录消费及可用观察 |
| generation/context/collect.py | 将指导作为独立上下文材料，与任务要求和 feedback 分开 |
| attribution/model.py 与归因状态 | 归因读取适用指导，输入身份包含实际指导版本和内容 |
| generation/stages/shared.py 及阶段材料 | 按用途提供已固定的指导，不要求模型再寻找核心指导 |
| generation/state.py 与持久检查点 | 绑定相同指导快照，恢复时验证来源、版本、权限和内容 |
| 经验来源适配器 | 兼容旧整体记录，并从当前类型化历史和实际观察提取有依据的关联 |

阶段契约按当前独立归因与生成入口调整，不能沿用旧 understand 阶段名称来假装覆盖独立归因。启动时可以为归因及生成各阶段准备分区的固定指导，整体保持有界预算；只使用当时已有事实，不预填本轮尚未得到的机制诊断。

初版保留显式条件匹配和稳定检索，不新增语义检索服务。能力、合同事实由宿主提供并纳入输入绑定，未知值不得由 Builder 猜测。语义适用性仍需当前角色核查，机制或词项匹配不是因果证据。

关闭经验入口或没有适用条目时保持原生成行为。经验非必要且检索不可用时，开始任务前明确记录未使用经验并走原流程；已经绑定有效包的任务若包失效，不得静默切换成无经验恢复，必须显式开始新的执行。

中断恢复沿用固定包和累计预算，新增经验只影响后续任务。复合 Harness 为根与子作用域分别校验受众和权限；同一联合改造的多个记录保持同一来源谱系，不能借作用域拆分增加证据。

使用日志区分入选、实际加载和观察到应用。文本注入不证明方法被遵循；必要时检查归因结论、实际代码改动和工具轨迹。程序或 Skill 资源还须遵守既有安装及执行权限。

数据库由宿主指定，位于版本库和 Worker 可写区域之外；共享权限与内容匿名化分别检查。源码接收和文档调整都在当前功能工作区进行，不修改交接工作区或其他开发人员的分支。

## 实施阶段与验证约束

| 顺序 | 工作及完成条件 |
| --- | --- |
| C1 接收完整基线 | 带入核心及未提交的准入检索文件，保存来源清单；独立运行原有测试，不覆盖当前 Curator |
| C2 接入公共协议 | 提取通用版本和决策能力，保留 Curator 证据规则；与 Rubric 接入共用治理行为 |
| C3 补齐经验修订 | 建立使用诊断、有限变更、替换关系与独立复验，验证冲突和撤销不可被洗掉 |
| C4 接通实际消费 | 完成归因、生成、根子作用域、指导表达、使用记录与检查点；开关关闭时通过兼容回归 |
| C5 接通后续学习 | 任务结束记录过程事实，真实后续观察补行为证据，新经验仅用于后续任务 |
| C6 验证跨任务价值 | 完成冻结经验库下的独立任务对照，并报告收益、退化和成本边界 |

C2 与 Rubric 方案的 R2 共用一份公共协议和一致性测试；源码层的复用不要求同步重写所有旧记录。先保存旧语义与迁移映射，再切换权威状态；历史导出不能继续作为第二个可独立更新的生效库。

C6 对比无经验、获准且等预算的原始历史参考、提炼指导三种条件。固定任务、Harness 基线、模型配置、工具权限、停止条件和评价依据；运行资源隔离，避免前一组修改污染后一组。预先确定重复次数和成功标准，不能选择性重跑到获胜。

目标指标包括实际行为达成、受保护能力是否退化，以及改造调用、token、耗时和代码改动成本。过程检查与最终业务结果分别报告。对照不能把更多预算、不同外部信息或额外能力造成的改善归给经验。

留出任务及结果不回流经验提炼库；验收报告可保留独立验证依据，但不能把同一批验收数据反复当作未见样本。真实模型、真实 Worker 和外部归档使用获准配置，缺资源按跳过报告。

原有 tests/test_experience_*.py 和跨进程测试继续保留。增补真实 Curator 消费、检查点失效、使用归因和跨任务对照的测试，不把 mock 验证当成实际改造收益。

## 验收场景

| 场景 | 预期结果 |
| --- | --- |
| Critic 接受但证据不足 | 保留候选，不向 Curator 正式推荐 |
| 一个来源的多输入或重放 | 不增加独立支持计数 |
| 通用 checked 或间接 held=True | 不能自动变成确切方法检查或行为收益 |
| supported 方法接入公共层 | 保留证据范围，按公共准入条件决定是否生效 |
| 只修改指导的一部分 | 无关经验不变，新内容重新评审并验证 |
| 新方法试图绕过旧矛盾 | 保留矛盾和来源关联，不能直接生效 |
| 正确经验没有进入归因上下文 | 修复装载，正文保持不变 |
| 归因与生成暂停后恢复 | 使用原固定包，相关来源失效时拒绝旧状态恢复 |
| 本任务学习出新经验 | 不回注当前任务，只用于后续独立任务 |
| 根子作用域与共享材料 | 接收者只见获准内容，拆分记录不制造独立证据 |
| 跨任务对照 | 使用未参与提炼的任务与固定条件，分别报告质量、退化和成本 |

完成 C1 至 C5 表示功能闭环接通；C6 决定可以声称多大范围的实际收益。若收益不成立，保留失败及反证，调整候选或适用范围，不降低准入规则来获得通过。

## 当前入口、预算与准入边界

simulation 和 iteration 命令通过 --experience-memory 指定宿主目录，--experience-scope 指定授权范围，旧库迁移显式使用 --experience-migrate；LiveConfig 提供对应字段。默认关闭。目录必须位于 Git 和 Worker 可写区域之外。Python 接入使用 CuratorExperience.from_provider，随后通过 experience 参数传入 improve 或 Session。

指导分为 diagnose、select、design、implement、repair 五个阶段；每阶段最多四条、8 KiB，完整条目渲染，实际请求记录加载事实。单个冻结包最多覆盖这五个阶段。正文显示过程或行为支持范围，不把入选或加载当成被遵循。失效包拒绝恢复；开始前可选存储不可用时明确记录无经验路径。

构建与内容审查默认合计最多四次调用，Builder 与 Critic 各最多两次，每次 60 秒。实际使用审计额外最多一次，按来源版本保存尝试记录；发生内容诊断时，转入同一有界构建预算的修订任务，不再同时提炼普通候选。单个来源版本的默认学习上限因此是一次审计加四次构建或审查调用，不应宣称仍然只有四次；宿主的独立验证执行采用单独预先固定的预算。

当前 initial admission 复用至少两个独立来源组的限定 process / behavior 证据，并绑定精确审查、策略、来源及消费形式；这只授予对应范围的指导资格，不声称跨任务增量收益。修订方法必须另经冻结任务对照，复现并修复所引用的问题且没有回退，不能借用旧方法支持数。

默认命令入口不会凭空生成修订的独立 oracle。宿主可向 from_provider 提供具有 identity 与 verify 的验证器，或调用 verify_repair 提供预先固定的 cases 和 evaluate；缺少验证器或独立证据时，修订保留候选。对照支持二至六个案例，默认每组执行上限 180 秒，来源或输入相同的案例不计为独立。

安装后才采集新的过程记录，正常任务中策略一致的独立评价再补行为观察。held-out 和比较运行拒绝学习回写。复合改造保留一个联合来源，不把整体收益分配给子项。学习失败或取消单独记录，已经完成的 Harness 安装事实保留。

## 本轮跨任务验证结果

本轮没有证明提炼指导相对无经验条件有增量收益，增益判定 accepted=false。功能链路已经通过验证，经验入口继续默认关闭；不能依据本次结果扩大经验的收益主张。

对照使用同一个真实 Curator 模型 deepseek/deepseek-flash、隔离的原生 Worker、相同的调用与探索上限，在两个未参与提炼的任务输入上各运行一次。来源任务要求实际 temperature 为 0.2、0.4，留出任务要求 0.1、0.6；环境读取真实 provider.request 参数作为目标 oracle，并检查回复执行没有错误。三种条件按任务轮换先后顺序。

| 条件 | 两个任务的成功情况 | 两个任务的模型调用数 | 调用总数 |
| --- | --- | --- | --- |
| 无经验 | 成功、成功 | 13、12 | 25 |
| 原始历史参考 | 成功、失败 | 12、14 | 26 |
| 提炼指导 | 成功、成功 | 13、16 | 29 |

各组都保留了本实验检查的回复执行能力。历史参考的第二个任务因未在探索预算内确认准备接口而没有实现目标；不追加预算重跑。提炼指导比无经验多四次调用，累计输入字符也更多，不能报告成本改善。字符量只是输入体积指标，本次未把它换算为 token、价格或长期吞吐收益。

经验内容由受控提炼器固定，用于隔离“提炼指导被真实 Curator 消费”的效果；真实 Experience Builder 和 Experience Critic 的构建、审查与审计另有模型测试。受控 Curator 加原生 Worker 的测试证明指导能改变实际参数，但不作为真实模型收益证据。这是单一机制、两个新输入、每条件一次运行的验证，不能外推到其他任务。

第一次真实对照中源码收尾修改触发了冻结检查，一组被拒绝，因此该轮不用于效果比较；随后按同样任务、预算和模型，在不可变源码快照中完整复验一次，以上为复验结果。原始失败记录保留，没有针对结果修改指导或重试到获胜。

可复验入口为 tests/integration/test_experience_curator_e2e.py。结果保存 study.json 及每组 comparison.json，包含实际请求、改造记录、执行证据和成本；运行产物放在 Git 外。功能验收通过与 Study 的增益判定是两个不同结论，后者未通过不会被改写为成功。
