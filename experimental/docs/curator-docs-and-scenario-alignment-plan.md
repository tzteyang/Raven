# Curator 说明与真实案例入口对齐计划

状态：说明与真实案例入口已实现，Planning 新协议已完成针对性验证。搜索凭据已补齐；此前旅行运行在业务执行阶段超时。本轮三例真实模型验证已结束：招聘完成构建和两轮交互，旅行与小红书因生成预算耗尽暂停，结果见 [产品案例验证记录](expert-package-validation.md)。历史阶段记录按其实际条件保留。日期：2026-09-29。

## 1. 目标与边界

本轮解决两个已确认问题：

1. 当前有效的代码说明、生成材料与导航统一使用四个 `*.strategy` 作为唯一语义生成入口，移除旧并行 Target 的误导；补齐策略选择、候选准备和根／子组合的理解路径。
2. 真实专家包案例使用正常数字员工的部署入口与可用能力。宿主提供现有基线和授权，Curator 决定业务分工，运行时根 Agent 决定实际调用；测试驱动不预先强制单层、强制委派或提供专家策略答案。

保留有效的公共方法、原生 Loop 与组合机制。只修复影响该入口的已确认迁移残留；不扩成任意新子角色注册、外部账号部署、Skill 元数据解析重构或全部行业材料清洗。对应限制必须可见，不能通过删掉要求来获得通过。

不修改用户提供的源专家包。不提交、不推送。历史运行记录保留真实内容，明确它们的旧版本身份；不将旧结果冒充新验证。

## 2. 方案选择

| 方案 | 代价与问题 | 结论 |
|---|---|---|
| 仅调整文档和测试计划，继续使用原临时单 Worker 脚本 | 最快，但真实入口仍与计划矛盾，无法解决第二个问题 | 不采用 |
| 建立全新的通用专家导入与评测框架 | 能力广，但重复现有 simulation/Curator/Worker 机制，扩大当前范围 | 不采用 |
| 复用现有员工准备、子基线托管与 Curator 流程，补小型专家材料入口和证据输出 | 同一部署规则，较少新机制；需要同步明确外部依赖与未完成验证 | 采用 |

成立前提：当前需求是在宿主支持的基线内构建专家；材料中的任意产品插件、账号和新子 Agent 身份并不自动成为宿主能力。如该前提变化，应单独评审能力接纳协议。

## 3. 说明清理与补强

### 3.1 现行理解入口

核对 `experimental/README.md`、`docs/design.md`、四策略 Protocol/docstring、Target.effect、公共参考、Raven adapter 参考、生成阶段提示及实际工具描述。首先修正错误，然后补充影响正确选择的内容，不按注释长度评价质量。

- 说明源码与资产的关系：策略代码决定采用，文件/JSON/Prompt/Playbook 不独立生效。
- 在初选概览中说明 prepare 所吸收的角色职责，特别是 Planning 的流程与子层 requirements。
- 区分 factory、候选 prepare、会话 initialize、每次模型输入/事件、换版与重启。
- 串起根规划、节点要求、子生成、整体验证、激活和实际委派；说明没有 requirements 不等于不能调用子 Agent。
- 区分宿主可选能力、Curator 的定制选择、运行时调用；不暗示 Curator 能任意新增子基线或改变授权。
- 更新旧接口示例和描述，历史迁移文件标明历史范围并指向当前说明。否定旧输入的测试和原始日志不机械重写。

复用现有 reference 和事实 schema，避免重复维护原生字段定义；示例仅解释通用机制，不提供完整领域专家实现。

### 3.2 阅读与验证

跟随实际材料生成链确认：初选得到职责概览，设计/实现得到所选协议和准备契约，组合根/子得到对应职责说明。对检索到的旧标识逐项判断是现行说明、历史证据还是拒绝旧格式的测试，不以全局字符串替换代替审查。

## 4. 案例入口调整

### 4.1 复用正常部署

复用 simulation 员工的基线准备与子 Harness 池；必要时提取一个由现有 hire 与专家入口共同调用的小型构造函数，避免两处维护部署规则。

保留宿主已配置且可用的工具、子 Agent 和授权。不得像旧旅行脚本那样为了简化测试批量关闭插件、spawn、run_subagent_dag、检索等能力。没有配置的服务如实报告，不为了宣称完整而伪造连接。

Curator 可以选择根层直接完成、使用既有子层或定制部分子层。判定依据是其计划、节点要求及实际执行记录，不是“子调用数量越多越真实”。本轮不把任意两层部署等同于每个任务都必须分工。

### 4.2 材料交接

完整暂存专家包中的文本和功能资源，包括隐藏 manifest、agents、rules、skills、嵌套参考、模板、脚本及来源说明。暂存只提供材料，不直接安装 Skill 或写专家 profile。

通过自然业务目标和中立文件索引交给 Curator；不提前分配四策略、写入固定 Playbook、压缩长画像成测试者摘要或替换原产品角色。原包与来源路径保持可追溯。评测任务和检查标准不提前泄漏给 Curator。

支持选择五个现有专家及独立输出目录；模型沿用已确认的 DeepSeek 配置。运行前后保存根／子可用情况、生成计划与产物、实际调用和失败证据，区分“可用”“要求定制”“已生成”“实际执行”。

### 4.3 最小实现修复

清理组合路径对已删除 `_content_baseline` 的访问，按当前安装账本与复制机制处理。修正结果导出调用，使用实际 Inspection 接口。只在相关失败证据要求时继续修复相邻路径。

## 5. 验证与停止条件

先做相关离线检查：正常部署构造确实提供子基线、完整材料保持原样且未自动激活、当前四策略知识链及父子组合生命周期。测试使用 `uv run pytest`，不扩大到无关全仓库回归。

入口通过后，优先做一次有界真实旅行验证，检查同模型下根 Curator 获得了真实子能力并自主选择流程；如果它选择根层独立完成，也保留该结果。外部依赖、模型预算或真实代码错误分别记录，不通过关闭能力或偷偷替换响应绕过。

五个案例的全量专家表现评估仍按更新后的 [专家包测试方案](expert-package-test-plan.md) 分批执行；本轮的入口验证不冒充五案例全面通过。模型调用与修复受既有预算限制，失败可留存，不能无限扩预算或反复抽样。

完成后独立复核本计划两项目标、更新旧计划中的暂停/未实施状态，并报告实际改动、验证结果、限制与新理解入口。文档变更执行大文件门禁。
