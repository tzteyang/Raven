# 待发队列推进与傍晚巡检值班说明

| 项目 | 内容 |
|---|---|
| 文件编号 | XSY-YY-ZB-002 |
| 版本 | V1.0 |
| 发布部门 | 运营部·会员运营组 |
| 生效日期 | 2026-09-15 |
| 适用范围 | 顾问助理（委托方）、线上值班同事（执行方） |
| 关联文件 | 《企微顾问服务规范》第 6、7 节 |

值班同事和顾问助理都没有直接给客户发消息的接口。移入已推送文件夹表示已在顾问的企业微信里生成一条待她本人确认的任务，不代表对客户已发出消息。汇报时只说推进到了哪一步，不说已发给客户。

## 1 什么时候委托值班同事

1.1 顾问当天不在店（培训、轮休、外出），而待发队列里有当天到点的已确认消息时，由顾问助理委托线上值班同事：到点把消息推进顾问的企业微信待确认任务，并在傍晚巡检一次客户动态。

1.2 只委托店长已经确认、已经入队的消息。没入队的不委托，也不让值班同事替你入队。

1.3 委托时把第 7 节的事项交代清楚。值班同事第一次回话只说明他接手了，不说明事情做完了；推进和巡检的结果以他后来的回报和巡检报告为准。

## 2 机器和巡检脚本

2.1 公司登记的机器是 Local lab（id `local-lab`，本机）。它的工作路径里放着巡检脚本 `queue_watch.py`。脚本只读业务消息：它读公司会员系统推来的客户动态和队列文件夹，不改队列消息；它会写自己的时钟和已看动态缓存。

2.2 用法：

```
python3 queue_watch.py --queue <工作目录里门店共享文件夹的绝对路径>/待发队列
```

上述相对脚本名只在 Local lab 登记的工作路径下有效：执行时明确进入该路径，或使用该路径下脚本的绝对路径。这个工作路径写在机器列表里 Local lab 那一行的备注中。登记路径不会自动改变 shell 的当前工作目录。每次读数都单独执行一次 `queue_watch.py`，不要放进值班任务的自动读数表里代读（自动读数只留下前几十个字，也留不下执行记录）；等待和读数分开做。

2.3 读数是什么意思。脚本每次输出若干行，每行一个 JSON：

- 第一行是总览：`store_time`（门店系统时间）、`reading`（这是第几次读数）、`next_check_seconds`（建议隔多少秒再读）、`pending`（待推送里的条数）、`pushed`、`withdrawn`（已推送、已撤回里的条数）。
- 之后每条待推送的消息一行：`file`（文件名）、`member`（会员ID）、`planned`（计划发送时间）、`due`（按门店时间是否已经到点）。
- 再之后每条客户动态一行：`at`（发生时间）、`member`、`kind`（`order` 新订单，`reply` 客户回复）、`channel`（渠道）、`detail`（订单内容或客户原话）、`new`（这一次读数才新出现的为 true）。

2.4 到没到点以 `store_time` 为准，不看机器的系统时钟（Local lab 用 UTC，和门店时间不一样）。

2.5 第一次读到待推送里有消息时，脚本开始计门店时间；在那之前读到的队列是空的，就先不算一次。

## 3 读数节奏和次数

3.1 第一次读数是起点。之后按 `next_check_seconds` 再读，一般不到一分钟。

3.2 一次值班最多读 10 次。

3.3 当天的待推送都处理完了（推进或撤回），并且 `store_time` 已过 17:30，再读最后一次作为傍晚巡检，然后写报告收工。计划在明天及以后的消息留在待推送里，不用等。

## 4 每次读数后做什么（只做这几件）

4.1 推进：`due` 为 true、而这位客户没有第 4.2、4.3 条的情况，把文件从 `待推送/` 移到 `已推送/`，在 `台账/触达台账.md` 追加一行"推送"。

4.2 撤回：这位客户在任一渠道下了纸尿裤或拉拉裤的新订单，或者回复了"这次先不用""家里还有"一类的话，而她的消息还在待推送里：把文件移到 `已撤回/`，台账追加一行"撤回"，"说明"里写原因（新订单写渠道和订单号，回复写原话）。

4.3 停发：客户回复"别发了""不要再发了"一类的话：她还在待推送里的消息全部移到 `已撤回/`，台账追加"停发"，在报告里请店长打勿扰标记。

4.4 客户回复了别的（道谢、提问）：不动队列，台账追加一行"回复"，原话写进报告，由顾问回她。

4.5 同一个文件只移一次。已推送的不再撤回；客户在推送以后才说不要的，写进报告请顾问处理。

4.6 不做别的：不改消息正文，不加新消息，不直接给客户发消息，不改客户档案。

4.7 值班同事登记的台账行，"登记人"写"值班"。

## 5 巡检报告

5.1 收工时写 `待发队列/巡检报告-<门店日期>.md`，比如 `巡检报告-2026-09-16.md`。

5.2 写这些：每次读数的 `store_time` 和看到的变化；推进了哪几条、各在什么时间；撤回了哪几条、原因；客户回复的原话；需要顾问或店长处理的事；留在待推送里的明天及以后的消息。

5.3 只写读数里看到的事，不猜原因，不替客户下结论。

## 6 中途汇报

委托人问进展时说清楚：已经读了几次、门店时间到几点、推进了几条、撤回了几条、有没有客户回复。还没收工就不说"已完成"。

## 7 委托时要交代的事项

| 事项 | 写什么 |
|---|---|
| 机器 | Local lab |
| 命令 | 第 2.2 节的命令，带上这次待发队列的绝对路径 |
| 看什么 | 待推送的消息到没到点；客户的新订单和回复 |
| 节奏和次数 | 按 `next_check_seconds`，最多 10 次 |
| 到点和有动态时做什么 | 第 4 节 |
| 什么时候停 | 第 3.3 节 |
| 结果写到哪里 | 队列文件夹、触达台账、巡检报告（第 5 节） |
| 汇报给谁 | 委托人；需要店长或顾问处理的写进报告 |
